# 手机竖屏 UI 设计方案（portrait-first）

> 状态：技术设计草案 v1（需求确认中），待评审。
> 关联：`web/app.js` / `web/style.css` 现有 `html.is-phone` 判定与横屏锁（`#rotate-gate`）、`MOBILE_CHECKLIST.md` 真机清单。

## 1. 现状（为什么要做这版）

- 现有手机端是**横屏专用**：`review.html` / `download.html` 在 `html.is-phone.portrait` 时显示「请横屏使用」全屏遮罩（`#rotate-gate`），竖屏进不去（`MOBILE_CHECKLIST.md` 第 3 条）。
- 横屏布局本身没问题：左侧文件树常驻 + 右侧 1 列卡片 + 灯箱左右分栏。但它**强制横屏**，竖握手机的用户被挡在门外。
- 本方案目标：**让手机竖屏可用且好用**，横屏继续走现有布局（不破坏已验收清单），`?ui=pc` 逃生口保留。

## 2. 设计原则

- **横屏优先、竖屏可用**：横屏是主推布局；竖屏进入仅给一条可关闭的软提示，不锁死，主流程（看图、标记、切目录）单手可完成。
- **复用、不重写**：文件树、卡片、灯箱、标记逻辑全部复用，靠 CSS 重排 + 少量 JS（抽屉、底部操作面板、点图隐 chrome）实现，不引入新框架。
- **大点击区**：标记按钮始终可见、够大（手指点得中），不靠 hover / 右键 / 双击。
- **安全区适配**：刘海 / 挖孔 / 底部 Home 指示条用 `env(safe-area-inset-*)`，不遮挡。
- **纯前端**：无后端 / DB 改动；行为状态仍走既有偏好（localStorage）。

## 3. 判定与方向

- 手机判定沿用现有 UA + 触摸 + `pointer:coarse` + 屏小判定，`?ui=phone/pc/auto` 覆盖保留。
- **保留横屏优先、竖屏仅软提示**：不删除 `#rotate-gate` 判定，但把它从「硬遮挡」改为「可关闭的轻提示」——竖屏进入时顶部出现一条可点「继续竖屏」关闭的提示条（「建议横屏获得最佳体验」），**不挡操作**；关掉后仍走下方竖屏新布局。这样横屏仍是主推，竖屏可用且不被锁死。
- 方向分流：
  - **竖屏（`html.is-phone.portrait`）** → 本方案新布局（下方第 4–5 节）。
  - **横屏（`html.is-phone:not(.portrait)`）** → 维持现有「左树 + 右 1 列」布局，**不改动**（保住 `MOBILE_CHECKLIST` 已验收项）。

## 4. 页面结构（竖屏）

```
┌─────────────────────────┐  ← 顶部栏（sticky，含安全区上边距）
│ ☰ 目录名…        👤 认领 │
├─────────────────────────┤
│ [全部][未定][已留][已弃] │  ← 细分段筛选（薄条）
├─────────────────────────┤
│ ┌──────────────┐     │
│ │   图① 大图   │ 1 列  │  ← 缩略图网格（竖屏 1 列大图）
│ │   ✓ ○ ✕      │ 卡片  │     每张卡底部常驻 ✓/○/✕
│ └──────────────┘     │
│ ┌──────────────┐     │
│ │   图② 大图   │     │
│ └──────────────┘     │
├─────────────────────────┤
│ 全留  全弃  清除  更多▾ │  ← 底部操作条（sticky，含安全区下边距）
└─────────────────────────┘
        ┌──────────┐
        │ 文件树…  │  ← 左侧抽屉（☰ 或左边缘右滑打开，背景遮罩，点遮罩关）
        └──────────┘
```

### 4.1 顶部栏
- 左：`☰` 打开文件树抽屉；旁边显示当前目录名（超长截断 + 省略号）。
- 右：`完成审阅 · 还有 N 张未定`（紧凑按钮）+ `认领此目录` / `释放认领` + 当前用户名（`👤 我` / 名字）。（完成审阅入口按用户拍板放**顶部栏**。）
- 用 `padding-top: env(safe-area-inset-top)` 避开刘海。

### 4.2 文件树抽屉
- 复用现有 `#tree` 组件，包进一个 `.drawer` 容器，从左侧滑入，`position:fixed` + 半透明遮罩。
- 打开方式：`☰` 点击、或从左边缘右滑（`touchstart` 起点 x<24 且横滑）。关闭：点遮罩 / 选完目录 / 左滑。
- 横屏保持不变（树仍常驻左侧，不进抽屉）。

### 4.3 缩略图网格
- 竖屏 **1 列大图**（用户拍板：大图更易看细节、单手扫图）。列数选择器在竖屏隐藏（固定 1 列）。
- 卡片：`object-fit:cover` 缩略图 + 文件名（单行截断）+ **底部常驻 ✓/○/✕ 三个大按钮**（不再需要进去才能标）。
- 卡片右上角保留 QC 徽标（`.qc-stack`），灯箱红框逻辑不变。
- 点卡片主体（非按钮区）→ 开灯箱。

### 4.4 细分段筛选 + 底部操作条
- 顶部薄条：`全部 / 未定 / 已留 / 已弃` 分段，复用现有过滤逻辑。
- 底部操作条（sticky）：`本页全留 / 本页全弃 / 清除本页` + `更多▾`（展开：画质切换、含父目录、刷新、完成审阅）。`完成审阅` 也可放这里或顶部。
- 用 `padding-bottom: env(safe-area-inset-bottom)` 避开 Home 指示条。

## 5. 灯箱（竖屏版）

```
┌─────────────────────────┐
│ ✕ 文件名 (1.2MB)        │  ← 顶栏：关闭 + 文件名/大小
├─────────────────────────┤
│                         │
│        [ 图片 ]          │  ← 居中，可双指捏合 / 按钮缩放，左右滑切图
│                         │
├─────────────────────────┤
│  ⟨ ‹ ⟩   原图 辅助线 框  │  ← 工具行：翻页 + 看原图 / 辅助线 / 问题框
├─────────────────────────┤
│   ✓ 保留   ○ 不确定   ✕  │  ← 标记操作面板（大按钮，自动跳下一张）
└─────────────────────────┘  ← 含安全区下边距
```

- **复用现有灯箱**：左右分栏的 `.lb-left`（标记）/ `.lb-right`（缩放）在竖屏下**重排到底部**——用 CSS 把这两个侧栏变成底部两行（工具行 + 标记行），基本无需改 JS。
- **左右滑动切图**：现有 `touchstart/move/end` 已有翻页逻辑，竖屏确认生效即可。
- **点图隐 chrome**：单击图片区切换顶/底栏显隐（clean view），再点恢复；不影响标记。
- **安全区**：顶栏 / 标记行加 `env(safe-area-inset-*)`。
- 辅助线（已做）、问题框（已做）按钮直接进工具行。

## 6. 关键交互清单

| 交互 | 竖屏做法 |
| --- | --- |
| 切目录 | ☰ 开抽屉选目录，或左边缘右滑 |
| 标记 | 卡片底部常驻 ✓○✕；灯箱底部标记面板（自动跳下一张） |
| 翻页 | 灯箱左右滑（手势）+ 底部 ‹ › |
| 缩放 | 双指捏合 + 工具行 ±；放大后可单指拖动 |
| 看原图 | 灯箱工具行「原图」按钮（单张临时） |
| 辅助线 / 问题框 | 灯箱工具行按钮（已实现的 G / H 对应功能） |
| 批量 | 底部操作条 全留/全弃/清除 + 更多▾ |
| 完成审阅 | 顶部栏（「完成审阅 · 还有 N 张未定」按钮） |
| 安全区 | 顶栏 / 底栏 / 标记行用 env(safe-area-inset-*) |

## 7. 与现有实现的改动点（纯前端）

- `web/app.js`：
  - 新增 `setupTreeDrawer()`：把 `#tree` 包进抽屉、绑定 ☰ / 遮罩 / 边缘滑动（仅 `is-phone`）。
  - 新增灯箱「点图隐 chrome」切换（仅竖屏）。
  - 卡片底部常驻标记按钮：在卡片渲染处加 3 个按钮并接 `decide()`（复用桌面已有逻辑）。
  - `#rotate-gate` 由硬遮挡改为「可关闭的轻提示条」：竖屏进入时显示、点「继续竖屏」即关，不阻挡操作（保留横屏优先语义）。
- `web/style.css`：
  - `html.is-phone.portrait` 下的栅格（1 列大图）、顶部栏、底部操作条、抽屉、灯箱底部重排、安全区 inset。
  - `html.is-phone:not(.portrait)` 维持现状（确保 `MOBILE_CHECKLIST` 不破）。
- `review.html` / `download.html`：`#rotate-gate` 改为**可关闭的软提示条**（不遮挡、点「继续竖屏」即关），保留横屏优先语义。

## 8. 验收

- 竖屏：页面正常渲染、无整页横向滚动；卡片含图+名+✓○✕ 同时可见且手指点得中。
- 抽屉开合、边缘滑动正常；选目录后网格更新。
- 灯箱：左右滑切图、双指缩放、底部标记面板、点图隐 chrome、辅助线/问题框按钮可用。
- 安全区：刘海/挖孔/Home 指示条下顶栏底栏不被遮。
- 横屏：行为**与现在完全一致**（左树常驻 + 右 1 列 + 左右分栏灯箱），`MOBILE_CHECKLIST` 22 条不破。
- `?ui=pc` / `?ui=phone` / `?ui=auto` 仍有效。
- 无后端 / DB 变更。

## 9. 工作量

**2–4 天**（纯前端，复用现有组件为主；最大头是竖屏 CSS 重排 + 抽屉/底部面板 JS + 安全区适配 + 横屏回归）。中低风险，但必须守住「横屏布局与现有清单完全一致」这条红线。

## 10. 决策已定（用户拍板）

- **横屏优先、竖屏仅软提示**：保留 `#rotate-gate` 判定，但由硬遮挡改为可关闭的轻提示条，不挡操作。
- **竖屏 1 列大图**（非 2 列）。
- **完成审阅入口放顶部栏**（「完成审阅 · 还有 N 张未定」按钮）。
- **先出可在手机直接打开试的 HTML 原型**（脱离后端、假数据），再正式实现；原型见 `web_demo/mobile_portrait_proto.html`。
