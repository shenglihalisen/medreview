# QC 判断阈值调节 UI 设计（审阅界面拖动调阈值）

> 状态：**待评审**（本文档 only，未动代码）。评审通过后再按第 12 节落地。
> 关联：`qc/qc.go`（阈值 const + 检测器）、`qcmanager.go`（后台 QC）、`store.go`（qc 表 / qc_version 失效）、`web/app.js`+`style.css`（审阅界面）、`docs/design/*`（既有设计文档约定）。

## 1. 目标与需求（你的原话）

在审阅界面加一个「调节」入口，点一下弹出窗口，用**拖动滑块**的方式调 QC 各检测器的**判断阈值**，调完看效果。

要解决的真实场景：你现在那套阈值是按约 14 张实拍校准的（宁漏勿滥、留 2–3× 余量）。有了滑块，你就能在自己的素材上**实时试**不同阈值、看判定怎么变，用来精调——而不是改代码重编译。

**本文要定的核心问题**：阈值目前是编译期常量，改成"界面可调"涉及 ① 运行时化 ② 持久化 ③ 改完怎么让旧结果作废重跑 ④ 大库重跑很慢怎么办 ⑤ 别让人随手一拖把校准值拖坏。下面逐个给方案 + 待你拍板。

## 2. 现状（关键架构事实）

| 事实 | 位置 | 对本案的意义 |
| --- | --- | --- |
| 阈值是**编译期 `const`**，检测函数直接比较 | `qc/qc.go` L59–108 | 要可调，必须先把 const 搬进一个运行时结构体 |
| `QCService` 是**单例** | `qcmanager.go:68` 建一个，包在 `QCManager` 里 | 阈值挂在它身上即可，全流程生效 |
| `qc` 表有 `qc_version` 列，读/`HasQC` 都按它匹配 | `store.go` 901/926/1125 | **现成的"作废重跑"通道**：版本不匹配就重算 |
| 有 `MetaStore`（`MetaGet/MetaSet` 键值）落 `meta` 表 | `qc.go:197`，现用于存硬件探测结论 | 阈值可持久化，重启不丢 |
| 单文件 QC 结果 = flags 位掩码 + detail JSON **整体存一行** | `store.go:890 SaveQC` | 改任一阈值 → 该文件整条作废 → **全库重跑**（见第 9 节成本） |

### 2.1 阈值清单（校准默认值 + 判定式 + 方向）

> ⚠️ 方向不一致：有的"调大更严"、有的"调大更宽松"，UI 必须逐个说清（第 10 节）。

| 检测器 | 常量 | 默认值 | 判定式 | 滑块调大的效果 |
| --- | --- | --- | --- | --- |
| 模糊 | `BlurLapStdThresh` | 15.0 | 拉普拉斯标准差 **<** 阈值 | 更严（更多标模糊） |
| 噪点 | `NoiseFloorThresh` | 5.0 | 噪声底线 **>** 阈值 | 更宽松（更少标噪点） |
| 空镜 | `BlankStdThresh` | 8.0 | 灰度标准差 **<** 阈值 | 更严（更多标空镜） |
| 欠曝 | `ExpUnderMean` | 100 | 平均亮度 **<** 阈值 且近黑>35% | 更严（更多标欠曝） |
| 过曝 | `ExpOverMean` | 150 | 平均亮度 **>** 阈值 且近白>80% | 更宽松（更少标过曝） |
| 抖动 | `ShakeRmsThresh` | 1.5 | 帧间平移 RMS **>** 阈值 且翻转率>50% | 更宽松（更少标抖动） |
| 重复 | `DupHammingThresh` | 5 | pHash 汉明距离 **≤** 阈值（候选） | 更严（更多标重复） |

**v1 先不暴露**（理由）：脏污 `DirtIoUThresh=0.5` 及污点局部参数（`smoothThresh`/`brightOutlier` 是动态算的，不适合滑）、曝光 clip 占比 `0.35/0.80`、重复像素确认 `25`/`5%`、视频 30% 投票、抖动翻转率 `0.5`。这些要么是跨照确认参数、要么是动态量，暴露了反而容易误用。**后续可按需再加。**

## 3. 方案总览

```
前端弹窗(滑块, 草稿值)
   │  点「应用并重新检测」
   ▼
POST /api/qc/thresholds  {blurLapStd:15, noiseFloor:5, ...}
   │
   ▼
QCManager.SetThresholds(t)  ── 持久化到 meta 表(qc_thresholds)
   │                          ── 阈值指纹变化 → qc_version 失效
   ▼
后台按新阈值重跑 QC（复用现有 QCManager + SSE 进度）
   │
   ▼
前端徽标/灯箱自动刷新（现有 qc 事件推送）
```

一句话：**把 const 阈值搬成"可运行时覆盖的结构体"，改值=存 meta + 让 qc_version 失效 + 后台重跑**。

## 4. 后端设计

### 4.1 阈值运行时化
- 新增 `qc.Thresholds` 结构体，字段 = 上表 7 个，**默认值 = 现 const**（保持默认行为零变化）。
- `QCService` 持有一份 `Thresholds`（`sync/RWMutex` 保护，QC 运行时读）。
- 检测函数把 `if lap < BlurLapStdThresh` 改成读 `s.th.BlurLapStd`（原 const 保留为 `DefaultThresholds()` 的初值，便于"恢复默认"）。
- 影响面：`qc.go` 里约 6 处比较点（L780/786/916/919/978/1092/1136/1139）改成读结构体。**纯机械替换，不改算法。**

### 4.2 持久化
- `QCManager.SetThresholds(t)` 时 `MetaSet("qc_thresholds", JSON)`。
- 启动时 `MetaGet` 读到就用、读不到用默认。→ 重启后你的调整值还在。

### 4.3 改完即失效重跑（关键）
- 现状 `qc_version` 写死 `QCVersion=5`。改为：**存库的 qc_version = 算法版本 + 阈值指纹**。
  - 用默认阈值 → 指纹为 0 → 等价现在的 5（默认结果可复用，不触发重跑）。
  - 任一阈值变化 → 指纹变 → 所有旧行 `qc_version` 不匹配 → `HasQC` 返回 false → 下次扫描/预热全部重算。
- 这比"改阈值就 `DELETE FROM qc`"更优：**改回默认值时，若没被覆盖过可直接复用缓存**（指纹归 0 又匹配上了）。
- 触发重跑：调完阈值后，对当前根目录跑一次全量 reconcile（复用 `QCManager` 现有逻辑），SSE 推进度。

### 4.4 API
| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/qc/thresholds` | 返回 `{current:{...}, defaults:{...}}` |
| POST | `/api/qc/thresholds` |  body=新阈值 → 校验/钳制 → 持久化 → 触发重跑 → 返回 `{ok, requeued:N}` |

- 校验：每个字段 clamp 到建议范围（防呆）；非法字段忽略并用默认。
- 鉴权：沿用现有令牌/同源校验（与其它 /api 一致）。

## 5. 前端设计

### 5.1 入口
- 审阅界面工具栏加一枚「调节阈值」按钮（与 QC 筛选、辅助线入口并列），图标用齿轮/滑块意象。

### 5.2 弹窗（点「调节阈值」弹出）
- 模态框，列出 7 个检测器，每行：
  - 左：中文名 + 一句白话判定（如"模糊：画面越糊越容易中"）
  - 中：**滑块**（拖动）+ 实时数值
  - 右：校准默认值（灰色小字）+ 「复位」小按钮（单行恢复默认）
- 顶部：「全部恢复默认」+ 一句提示"默认值已用实拍校准（宁漏勿滥）"。
- 每行滑块旁标注方向提示，如「← 更宽松 · 更严 →」（按第 2.1 表的方向，逐个写对）。
- 底部：**「取消」** / **「应用并重新检测」**。
  - 滑块拖动只改**草稿值**，不触发任何重跑；只有点「应用」才提交 → 避免每拖一格就跑全库。

### 5.3 应用后的反馈
- 点「应用」→ 弹窗显示"正在按新阈值重新检测…（N 个文件）"进度（复用现有 `/api/qc/status` + SSE），完成后 toast"完成，徽标已更新"。
- 未应用直接关弹窗 = 放弃本次拖动（不改任何东西）。

## 6. 数据流时序

1. 用户点「调节阈值」→ `GET /api/qc/thresholds` 填充弹窗（草稿=当前值）。
2. 拖滑块改草稿值（纯前端，无请求）。
3. 点「应用并重新检测」→ `POST /api/qc/thresholds`。
4. 后端：clamp → `SetThresholds` → 存 meta → 阈值指纹变 → qc_version 失效 → 异头调度全量重跑 → 返回待重跑数。
5. `QCManager` 后台逐文件重算，SSE 推 `qc` 事件；前端徽标/灯箱随之刷新。
6. 持久化阈值重启后仍在；「全部恢复默认」→ 指纹归 0 → 复用默认缓存。

## 7. 交互 / UX 细节

| 项 | 建议 |
| --- | --- |
| 滑块范围 / 步长 | 按第 2.1 各检测器给 min/max/step（模糊 5–60/1，噪点 1–20/0.5，空镜 2–30/0.5，欠曝 30–160/5，过曝 90–220/5，抖动 0.3–6/0.1，重复 0–15/1） |
| 数值显示 | 保留 1–2 位小数，实时跟着滑块走 |
| 方向可读性 | 每个滑块旁一句"调大→更严/更宽松"（**这是最大易错点，方向不一致，务必逐个核对**） |
| 默认值保护 | 常驻显示校准默认值 + 单行/全局复位；提示"默认经实拍校准" |
| 草稿隔离 | 拖动不落库、不重跑；仅「应用」提交 |
| 移动端 | 弹窗自适应窄屏；滑块触控友好（`input[type=range]`） |

## 8. 关键难点与权衡（附推荐）

**① 重跑成本（P0）**：单文件 QC 结果整条存，改任一阈值 → **全库重算**。图片快，**视频慢**（要抽帧解码）。库大 + 视频多时可能几分钟~几十分钟。
- 推荐 v1：应用后**后台全量重跑 + 进度条**（校准本就要看全库效果），弹窗明确提示"将重新检测全部 N 个文件"。
- 备选：仅重跑当前目录（快，但只影响一层）——你若常按文件夹校准，可选这个。

**② 别把校准值拖坏（P0）**：你一贯"未校准不许上线/宁漏勿滥"。
- 缓解：默认值常驻 + 一键全局复位 + "默认经实拍校准"提示；滑块范围做钳制，拖不出物理合理区。

**③ 方向可读性（P1）**：拉普拉斯std/噪声底线不直观，且 7 个方向不一致。
- 缓解：每行白话 + 显式"调大→严/松"；必要时加一句指标解释。

**④ 持久化 vs 默认（P1）**：调整值重启后还在，等于"改了默认"。
- 缓解：区分「当前值」与「校准默认值」两列显示，复位一步回到校准态。

## 9. 风险与缓解

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 大库/视频多时全量重跑卡顿 | P1 | 后台跑 + 进度条；可改"仅当前目录"范围 |
| 阈值钳制范围不合理，拖不到有效值 | P1 | 范围按实拍分布 ±2–3× 设，文档列明 |
| 指纹/失效逻辑写错导致不重跑或反复重跑 | P0 | 回归：改值→必重跑；改回默认→复用缓存；加验收断言 |
| 与既有 QC 逻辑冲突 | P0 | 只把 const 比较改成读结构体，算法零改；跑全套 harness |
| 并发改阈值时正在跑的 QC | P1 | RWMutex 快照当前阈值用于本次运行，下次生效 |
