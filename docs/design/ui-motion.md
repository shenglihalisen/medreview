# 界面过渡与交互性设计（动效打磨方案）

> 状态：**待评审**（只出方案，未动代码）。
> 关联：`web/style.css`、`web/app.js`、`web/standalone*.html`（内联副本）、`docs/design/qc-thresholds.md`（阈值弹窗为本轮新增的 UI，一并纳入）。

## 1. 目标与原则

**你的原话**：让界面在一些地方有**过渡**和**交互性**。

**定位**：medreview 是审阅工具，节奏快、批量操作多。动效的目标是**让状态变化可被看见**（弹窗从哪来、卡片到哪去、QC 结果怎么变），而不是炫技拖慢审阅。

**四条硬原则**（贯穿全部条目）：
1. **只动合成层**：动画只允许 `transform / opacity / filter`——绝不过渡 `width/height/top/left`（触发重排，大网格必卡）。
2. **时长预算**：微交互 120–200ms、进出场 ≤250ms，全部 ease-out 系。超过 250ms 的动画在这个工具里都是打扰。
3. **`prefers-reduced-motion: reduce` 全局一刀切禁用**（一条 media query）。
4. **大库保护**：进场/FLIP 类动画只作用于视口内元素；卡片总数超阈值（500）自动降级为直接切换。

## 2. 现状盘点

| 位置 | 现状 | 问题 |
| --- | --- | --- |
| 弹窗（modal/名字门禁/阈值弹窗） | `display:none → flex` 瞬间出现 | 生硬，无来源感 |
| 灯箱图片切换 | 瞬间替换（只有缩放 transform 有 .22s 过渡） | 换图跳跃，翻页无方向感 |
| 卡片进场/筛选/列数切换 | 整块重渲染，瞬间闪现 | 大批量出现时视觉突兀 |
| QC 徽标 | 重跑后瞬间闪现 | 看不出"更新了" |
| 按钮 hover | 只有背景变色 | 无按压/深度反馈 |
| toast | 已有 opacity .2s 淡入 | 缺位移，存在感弱 |
| 目录树/骨架屏/重跑进度 | 无 | 加载空窗期纯白 |
| 全站 @keyframes | **0 个**；全站 transition 仅 2 处 | 基础设施从零建（也意味着没有历史包袱） |

## 3. 提案清单（分级）

### P0 纯 CSS（低成本高质感，建议必做）

| # | 项 | 现状 → 改成 | 实现 |
| --- | --- | --- | --- |
| 1 | 弹窗统一进出场 | 闪现 → 背景淡入 + 内容 `scale(.96)→1` + `translateY(8px)→0`，180ms；关闭反向 120ms | `#modal/#name-gate` 由 display 切换改为 `opacity+visibility` 组合过渡（JS 仍只 toggle `.on`，**零 JS 改动**）；阈值弹窗复用 modal 自动获得 |
| 2 | 按钮按压反馈 | hover 变色 → 加 `:active scale(.97)` + transform .12s 过渡 | 纯 CSS |
| 3 | 卡片 hover 深度 | 只有描边变色 → `translateY(-2px)` + 轻阴影，.15s | 纯 CSS；保留现有 border 高亮 |
| 4 | QC 徽标淡入 | 闪现 → `opacity+scale` 180ms 进场（keyframes） | 纯 CSS，作用于 `.qc-stack span` |
| 5 | toast 增强 | 淡入 → 淡入 + `translateY(6px)→0` 滑入 | 纯 CSS |
| 6 | 灯箱换图淡入 | 瞬间替换 → 旧图淡出新图淡入（**只动 opacity**，不碰 zoom 用的 transform，避免冲突） | JS 在换图时给 img 加一个一次性 class（唯一 P0 JS 改动，约 5 行） |
| 7 | 分段按钮/筛选 `.on` 态 | 变色瞬间 → background/color .15s 过渡 | 纯 CSS |

### P1 JS 配合（中等，建议按需选做）

| # | 项 | 内容 | 实现 | 成本 |
| --- | --- | --- | --- | --- |
| 1 | 卡片 stagger 进场 | 新出现卡片依次淡入+上移，每张 +20ms、封顶 160ms | CSS keyframes + `style.animationDelay`；只用 opacity/transform | 小 |
| 2 | 加载骨架屏 | 进目录/扫描空窗期显示 8 张脉冲骨架卡，数据到位交叉淡出 | 静态骨架 DOM + shimmer keyframes | 中 |
| 3 | 阈值重跑进度条 | 「应用并重新检测」后弹窗**不关**，切换成进度态（已重算 N/M + 微进度条），完成后变"完成，徽标已刷新"并自动关闭 | 轮询 `/api/qc/status`（已有接口）或复用 SSE qc 事件计数 | 中 |
| 4 | 目录树展开/折叠过渡 | 高度/透明度过渡 | 树是 JS 重渲染，需包 wrapper 动 `grid-template-rows` | 中，收益一般（树不常开合）→ 可选 |

### P2 重活（出彩但易出事故，默认不做，点名才做）

| # | 项 | 说明 | 风险 |
| --- | --- | --- | --- |
| 1 | 列数切换/筛选 FLIP 动画 | 卡片从旧位置平滑滑到新位置（First-Last-Invert-Play） | 大网格性能事故高发区；必须视口内限定了 + >500 卡自动降级 |
| 2 | 灯箱触摸滑动手势 | 手机横屏左右滑翻页（跟手位移 + 松手回弹/翻页） | 触摸逻辑与缩放手势冲突要理清 |
| 3 | 徽标 tooltip | 悬停徽标显示指标解释与估算值含义 | 简单但价值低 |

## 4. 方案打包（选一个）

| 打包 | 内容 | 工作量 | 效果 |
| --- | --- | --- | --- |
| **A 克制版** | P0 全部（纯 CSS + 灯箱 5 行 JS） | 半天级 | 弹窗/按钮/卡片/徽标全部"有生命感"，零性能风险 |
| **B 推荐** | A + P1-1 stagger 进场 + P1-2 骨架屏 + P1-3 重跑进度条 | 一天级 | A + 加载空窗有交代 + 阈值重跑可视化 |
| **C 完整版** | B + P2（FLIP + 触摸手势） | 两天级+ | 全面但引入性能风险面 |

**我的推荐：B。** P0 是纯赚的；stagger 进场和骨架屏直接提升"打开就专业"的第一印象；重跑进度条跟刚做的阈值功能是天然配套（你上次应用后只有一条 toast，进度条让"全库重跑"可感知）。

## 5. 落地注意（实现时执行）

- 三份 CSS 同步：`style.css` + `standalone.html` + `standalone_dl.html` 内联（沿用本轮阈值弹窗的同步方式）；JS 同步三份。
- 验收：`prefers-reduced-motion` 下全站静止；500+ 卡模拟库无卡顿（DevTools Performance 面板录一遍）；弹窗连续开关无闪烁；harness 不受影响（纯展示层，mobile_shell 的结构断言需过一遍）。
- 不引入任何动画库（零依赖，纯 CSS + 少量原生 JS）。
